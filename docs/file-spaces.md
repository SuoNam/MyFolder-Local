# 公共区与个人文件区

## 使用方式

文件页新增三个入口：

- **我的文件**：仅当前登录账号能通过 Web/API 访问的个人空间，所有角色默认 5 GiB（界面显示为 GB），可自行上传、下载、创建、修改和删除。
- **公共区**：同一后端的所有已登录账号（包括新审核通过的账号）默认可浏览、下载。普通用户的上传/新建、修改/移动、删除分别由管理员授权，互不隐含；管理员有公共区完整管理权限。匿名访客不可访问。
- **原授权目录**：保留升级前 `files/` 的文件与路径授权，仅对原来可见的账号显示。不迁移、不删除旧文件，不自动将旧文件公开到公共区，也不猜测旧文件属于谁。

管理员进入“用户与权限 → 个人配额与公共区权限”，选择账号，设置个人空间配额及公共区三个写权限后保存。普通管理员可管理普通用户和自己的配额；其他管理员/超级管理员账号仅由超级管理员管理。此操作只显示空间用量和配置，不开放他人的私人文件内容。

原“路径授权”仍针对原授权目录，与新增公共区权限分别管理。公共区当前按账号授权，权限覆盖整个公共区及子目录，不是子目录分级 ACL。

## 配额规则

- 每个账号独立统计个人文件字节数，初始上限 `5368709120` 字节；管理员可设置 1 字节至 1 PiB，不需要重启服务。
- 个人配额是上限，不预留磁盘。原服务器总容量上限仍生效，统计原目录、公共区、全部个人目录（包括删除账号后保留的文件）；总上限需由超级管理员在“服务器信息”调整。
- 并发上传同时检查个人配额、服务器总上限及已预留的上传增量；接收完成后再次检查，再原子替换目标文件。失败时不覆盖原文件，并清理该上传临时文件。
- 覆盖按新旧文件差额计费；相同大小或更小的覆盖不增加占用。配额调低到已用量以下时不删文件，仍可下载、删除或缩小文件，但新增增长会被拒绝。
- 公共区和原目录占用服务器总容量，不计入上传者的个人配额。目录在同一文件区内移动/改名不改变占用；当前不提供跨区直接移动。
- 上传中的目标及其父目录不能被同时移动/删除；不同用户同名文件互不争用个人目录的上传预约。

## 隔离与兼容

- 个人根目录为 `MYFOLDER_DATA/personal/<随机存储标识>/`；公共根目录为 `MYFOLDER_DATA/public/`，原目录仍为 `MYFOLDER_DATA/files/`。
- 不使用用户名或可复用的用户 ID 作为个人物理目录名。删除账号会删除配额/公共授权记录，但保留原私人文件，防止误删；新建同名账号或 SQLite 重用 ID 时使用新的随机标识，不继承旧文件。
- 删除账号后保留的数据仍计入服务器总占用；本轮不提供孤立目录清理按钮。回收需服务器维护者先确认备份及归属，不应直接按用户 ID 猜目录删除。
- 客户端只能选择个人/公共/原目录，不能提交任意个人目录标识。个人文件接口始终使用当前认证账号，传入其他 `user_id` 不会切换所有者。
- 拒绝路径遍历和符号链接访问，打包仅包含当前文件区内有下载权限的文件；Windows 测试构建还拒绝驱动器、NTFS 附加流和末尾点/空格路径。
- 密码重置尚未完成的临时登录不能访问新增空间接口。账号删除/重建、公共授权或配额变化在上传提交时复核。
- 外连服务器继续使用原目录和原有双侧授权，不自动暴露新的个人/公共目录给服务器凭据。
- 私人隔离是应用权限边界，不抵御拥有服务器操作系统/数据库权限的维护者读取磁盘。

启动升级新增 `user_storage`、`public_grants` 两张表，不修改现有用户、密码、会话、旧路径授权和旧文件内容。`cpp/src/spaces.h` 已加入源码 deb 清单。升级仍须备份 SQLite（含 WAL）、配置及整个数据目录。

## 接口

- `GET /api/spaces`：当前个人用量/配额、公共区权限、服务器总用量和原目录可见性。
- `/api/spaces/personal/{list,download,folder.zip,mkdir,move,delete,upload}`：当前账号个人区。
- `/api/spaces/public/{list,download,folder.zip,mkdir,move,delete,upload}`：公共区。
- `GET /api/admin/storage`：管理员可管理的账号空间及公共权限列表。
- `POST /api/admin/storage`：`user_id`、字节数 `storage_limit`、布尔 `public_upload/public_modify/public_delete`，原子保存。
- 原 `/api/list` 等文件接口不变，继续访问原授权目录。

## 自动化与人工清单

构建 Web 后，设置 `MYFOLDER_CPP_BINARY` 指向测试二进制，运行：

```sh
python -m unittest discover -s tests -p 'test_*.py' -v
```

新增 `tests/test_spaces.py` 覆盖私人隔离、公共区可见性和独立写权限、配额/缩容/覆盖、并发预留、总容量、管理员越权、ID 重用、旧数据升级、重启持久化与路径边界。Windows 会跳过 Linux 符号链接检查，Linux 会跳过 Windows 路径检查，不能将跳过项算作已验证。

`tests/check_spaces_ui.py` 连接隔离的真实后端，使用两个独立用户浏览器，验证移动端/桌面文件切换、私人隔离、公共区只读、管理员授权上传和超额拒绝。原免密、注册审批、外连及六种屏幕布局回归仍需运行。

- [ ] 用户甲上传私人文件，用户乙及其他管理员账号不能从应用读取；公共区看不到该文件。
- [ ] 新注册审核通过后可用个人空间、读公共区；未授权不能上传或覆盖公共文件。
- [ ] 管理员分别授予上传、修改、删除，实际按钮与后端行为一致；撤销后立即拒绝对应操作。
- [ ] 配额增大/缩小正确，删除与覆盖用量正确；并发上传不会超额，不同用户同名文件不冲突。
- [ ] 服务器总上限仍有效；旧文件仍在原授权目录，权限不变，不自动公开。
- [ ] 重启保留配额、公共权限和个人文件；删除重建账号不继承私人数据。
- [ ] Linux 实机检查符号链接拒绝、目录保存权限、大文件、磁盘不足及备份回滚。
