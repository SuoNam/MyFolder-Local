# 用户注册审批与可信浏览器免密

## 使用方式

1. 登录页选择“申请注册”，填写 3–64 位账号（字母、数字、下划线、减号）、至少 8 位密码和设备名称。
2. 在个人浏览器中，可勾选“同时申请此浏览器免密登录”。默认内网 HTTP 即可使用，不需要先配置证书；HTTPS 为可选增强。
3. 管理员在“用户与权限 → 注册申请审核”批准或驳回。显示“含浏览器免密申请”的记录，通过时会一并批准这个浏览器。
4. 申请人可留在页面自动检查，或点“检查审核结果”；获批后会自动领取一次性登录资格并进入账号，领取失败时可点“审核通过，进入账号”重试。保留注册收据的同一浏览器重新打开页面时，也会检查并自动领取；也可使用注册密码登录。
5. 新注册账号默认没有文件权限；管理员需在路径授权中为其分配权限。原有管理员手动创建账号及其默认权限保持不变。
6. 现有账号在“登录设备”提交免密申请。普通账号由管理员或超级管理员审核，管理员和超级管理员设备仅由超级管理员审核（超级管理员可审批自己的设备）。
7. 同一浏览器再次访问时，可自动恢复短期登录会话；会话过期后的普通 API 请求会尝试一次免密恢复并重试，恢复失败则回到登录页。
8. 审核后如果手动输入账号密码登录，同一浏览器仍保存有效、未领取、与该账号匹配的已批准注册收据时，也会自动完成免密领取，不再依赖停留注册页轮询。错误密码不会消费收据。
9. 登录后页面会明确显示“免密已开启”或“临时登录”；“登录设备”可查看当前浏览器实际状态。注册通过不等于任意浏览器免密已开启，待审、被驳回、已撤销或过期的设备不会自动恢复资格。
10. 暂时离开可直接关闭浏览器；点击“退出登录”会主动撤销此浏览器免密。应使用同一浏览器配置和相同服务器主机地址；无痕模式、清除 Cookie 或更换访问主机地址不能沿用原浏览器凭据。

## 安全和边界

- 识别的是持有专用 Cookie 的浏览器配置，不是物理电脑，也不是 MAC。换浏览器、无痕模式、清理 Cookie 后需重新申请；不能保证复制浏览器配置后仍绑定原硬件。
- 免密凭据为 256 位随机值，数据库只存 SHA-256；浏览器以 HttpOnly、SameSite=Strict Cookie 保存，HTTPS 下增加 Secure，不写入 localStorage。
- 凭据仍属于敏感身份凭证；Cookie/浏览器资料被完整窃取时存在冒用风险，管理员应及时撤销。设备名称仅用于展示，不用于验证身份。
- 注册收据和待审核设备申请有效期 7 天；获批免密最长 90 天，连续 30 天未使用过期。
- 免密恢复时轮换凭据。旧值仅留 30 秒用于识别多标签页竞争，不再用于创建会话；同一页面内并发请求合并为一次恢复。
- 账号密码、注册审批、设备审批和文件路径权限是独立校验。客户端传入管理员角色不会使注册账号获得管理员权限。
- 管理员撤销时删除该设备关联的免密会话；用户退出时撤销当前浏览器并清除相关 Cookie，其他设备不受影响。退出接口也能处理已过期的普通会话。
- 密码重置审批及完成改密会撤销全部可信设备、旧会话和未领取的注册登录资格。
- 账号注册、密码登录及免密接口有基础频率限制；单用户最多 20 台有效的待审核/已批准浏览器，待审核注册总数最多 500。
- 本版本不允许用户自行变更角色，也不允许通过免密流程跨账号访问设备信息或审核列表。
- 仅有账号密码或账号已获批，不会批准一个没有浏览器收据的新浏览器；手动密码登录不能重新激活待审、驳回、撤销或过期设备。没有有效证明时，页面提示临时登录，需重新提交浏览器免密审批。

## 默认 HTTP 与可选 HTTPS

默认通过 `http://服务器内网地址:8080/` 即可注册、审批、使用密码登录以及申请、领取和恢复浏览器免密，无需设置额外环境变量。页面在 HTTP 下提示通信未加密，但不禁用申请按钮。

HTTP 不加密密码、登录凭据和文件内容，仅应在可信内网使用；不能把管理员审核、私有 IP、HttpOnly 或 SameSite 视为传输加密。不要将默认 HTTP 端口直接映射到公网。

需要 HTTPS 时可选配反向代理，向后端覆盖写入 `X-Forwarded-Proto: https`。`MYFOLDER_TRUSTED_PROXY_IPS` 默认只信任 `127.0.0.1,::1`，其他代理须明确填写其实际源地址，不能任意信任外部客户端。可信 HTTPS 入口会自动为认证 Cookie 增加 `Secure`；应将后端绑定回环或用防火墙限制直连。使用内部 CA 时，访问设备仍需信任其根证书。

可选 `MYFOLDER_REQUIRE_HTTPS_DEVICE_LOGIN=1`：仅强制免密申请、含免密的注册、注册免密领取和免密恢复使用可信 HTTPS；普通注册、密码登录和审批不受该开关限制。它不是 TLS 服务器开关，不负责安装证书、跳转 HTTPS 或禁止所有 HTTP 请求。默认值为 `0`，常规内网部署无需填写。

可信边缘代理应将实际客户端地址追加到 `X-Forwarded-For`（例如 Nginx 的 `$proxy_add_x_forwarded_for`）；限流取可信代理转发链的最后一个地址，不采用客户端可伪造的首项。未受信任的连接会忽略该头。多个用户确实共用同一出口 IP 时仍共用基础限流窗口，批量开户可用管理员创建用户。

旧的测试用 `MYFOLDER_ALLOW_INSECURE_DEVICE_LOGIN` 已移除，不再影响行为。HTTP 是产品默认模式；浏览器测试也不再设置该开关。HTTP 模式保持注册审批、设备审批、凭据轮换、有效期、撤销及文件权限检查。

## 数据迁移及发布

启动时创建 `registration_requests`、`trusted_devices`，为原 `sessions` 增加可空的 `device_id`。不删除已有账号、文件、权限和会话。部署前仍应停止写入并备份 SQLite（含 WAL）及上传目录；旧版二进制不兼容新增后的整行 INSERT，回滚必须恢复匹配版本的数据库备份，不能直接降级二进制。

新增模块位于 `cpp/src/auth.h`，已加入源码 deb 文件清单。2026-10-25 已替换 rk3528 的生产服务和 Web，数据库迁移及备份信息见 [部署记录](deployment-2026-10-25-auth.md)。旧 v1.5.0-1 Release 安装包未重新发布，不包含本轮功能。
