# 注册审核与浏览器记住登录

## 当前规则（2026-10-26）

只审核账号，不再单独审核浏览器。已获批或管理员创建的账号，使用正确密码登录后默认记住当前浏览器；有效期由超级管理员配置，初始默认 90 天，可设为长期有效。不要求保留最初注册的浏览器收据。此规则替代早期的“注册时同时申请免密 / 现有账号另行申请设备审批”。

### 注册与登录

1. 登录页选择“申请注册”，填写账号、密码和浏览器名称。账号为 3–64 位字母、数字、下划线或减号，密码至少 8 位。
2. “审核通过后记住此浏览器”默认勾选，按当前策略显示天数或“长期”；公共电脑可取消。管理员只需批准注册；申请页面会查询结果，获批后可凭一次性注册收据自动进入。
3. 如果关闭过申请页面、收据丢失或选择手动登录，账号获批后直接输入正确密码即可。登录页的记住选项默认勾选，无需再申请或审批浏览器。
4. 新注册账号默认没有文件权限，需由管理员另行授予。管理员手动创建账号的原有权限规则不变。
5. 登录后页面显示“免密已开启”或“本次未记住浏览器”。“登录设备”中可查看期限、修改名称、记住当前浏览器或撤销旧浏览器；管理页保留查看、撤销权限，不再显示浏览器通过/驳回按钮。
6. 暂时离开可直接关闭浏览器。使用同一浏览器配置和同一服务器主机地址再次访问时，会自动恢复登录；会话过期后的 API 请求也会尝试一次免密恢复并重试。
7. 点击“退出登录”会撤销当前浏览器，下一次需输入密码。不应把主动退出当成关闭窗口。登录时取消勾选也会移除当前浏览器的长期凭据，只保留本次短期登录。

### 管理免密有效期

- 入口为“用户与权限 → 浏览器免密设置”。全服务器策略仅超级管理员可修改，普通管理员只读，普通用户不可访问管理接口。
- 可设置 1–3650 个整天，或“长期有效（直到撤销）”；原有部署升级默认保留 90 天，不自动改为长期。
- 指定天数模式从密码登录/主动记住时计算绝对到期时间，普通访问和自动恢复不延长服务端期限。
- 长期模式使用服务端 `expires_at=0` 表示不主动到期，不再用未使用天数过期。浏览器 Cookie 每次最多签发 400 天，在启动查询 `/api/me`、查看登录设备或自动恢复时刷新；不是保证浏览器永远保存网站数据。
- 确认更改策略后，只对当前有效的已记住浏览器从保存时按新规则重新计时。过期、撤销、驳回和旧待审记录不被恢复；保存相同值不改变期限。
- 服务端规则立即更新；其他浏览器的本地 Cookie 只能在下次访问时更新。延长期限后，若某浏览器在旧 Cookie 到期前一直未访问，仍可能需要密码登录。当前管理浏览器保存后即刷新 Cookie。
- 不再有“连续 30 天未使用提前过期”的规则。
- 同一账号最多保留 20 个有效浏览器；新增第 21 个时撤销最久未使用的记录及其关联会话。
- 管理员撤销、主动退出、密码重置、浏览器清理 Cookie 等会提前终止记住登录。
- 无痕模式、清理网站数据、换浏览器配置、换 IP/域名不能沿用原 Cookie；重新正确密码登录即可记住，不需要额外设备审批。浏览器若配置为退出时删除站点数据，也无法跨重启保留。

## 凭据和权限边界

- 识别的是浏览器持有的随机凭据，不采集 MAC 或浏览器指纹，也不声称绑定物理硬件。
- `mf_device` 为 256 位随机值，数据库只保存 SHA-256。Cookie 为 HttpOnly、SameSite=Strict，Max-Age 不超过服务端剩余期限和 400 天（长期模式为 400 天）；可信 HTTPS 下增加 Secure，不写入 localStorage。
- 普通 `session` Cookie 不设持久期限，服务端会话有效期 24 小时。关闭浏览器后由长期凭据恢复短期会话；不是把普通 session 改成永久有效。
- 自动恢复会轮换长期凭据。旧值只保留 30 秒识别多标签页竞争，不能再创建会话；同页并发恢复会合并。
- 注册收据有效期 7 天，只能领取一次；密码登录记住浏览器不依赖该收据。错误密码、待审核/驳回的注册不会获发长期凭据。
- 被撤销的旧凭据永远无效。持有正确密码重新登录会获发新凭据，而不是复活旧值；撤销不是禁用账号或作废密码。如密码也泄露，应同时重置密码。
- 退出只撤销当前浏览器，不影响其他浏览器；密码重置审批及完成改密会撤销所有旧浏览器、旧会话和未领取的注册收据。临时重置密码登录不能获得长期凭据。
- 管理员可撤销普通用户浏览器；管理员及超级管理员的浏览器仅由超级管理员管理。普通用户只能管理自己的记录。文件路径权限、角色校验不因记住登录而放宽。
- 凭据被窃取可能被冒用。账号注册、密码登录及免密接口保留基础限流；待审核注册总数上限 500。

## 默认 HTTP，HTTPS 可选

默认 `http://服务器内网地址:8080/` 开箱即用，注册、审批、密码登录及长期登录无需额外环境变量或证书。

HTTP 不加密密码、登录凭据或文件，只适用于可信内网。私有 IP、HttpOnly、SameSite 和账号审核不能代替传输加密，不要把默认 HTTP 端口直接映射公网。

可选 HTTPS 反向代理：覆盖写入 `X-Forwarded-Proto: https`，并在 `MYFOLDER_TRUSTED_PROXY_IPS` 中配置实际代理源 IP（默认只信任 `127.0.0.1,::1`）。可信 HTTPS 下认证 Cookie 会带 Secure；应限制后端仅代理可达。使用内部 CA 时，访问设备需信任该 CA。

可选 `MYFOLDER_REQUIRE_HTTPS_DEVICE_LOGIN=1` 只限制长期凭据的建立、领取和恢复，不影响普通密码登录。HTTP 密码登录仍成功，但不会记住浏览器，页面会提示改用 HTTPS。该开关不负责安装证书、自动跳转 HTTPS 或禁止所有 HTTP。默认值为 `0`。

可信代理应将实际客户端 IP 追加到 `X-Forwarded-For`；限流使用可信代理转发链最后一项，不接受客户端伪造的首项。不受信任的连接忽略此头。多人共用出口 IP 时仍共用基础限流窗口。

## 兼容与部署

认证模块位于 `cpp/src/auth.h`，已进入源码 deb 清单。启动时创建 `registration_requests`、`trusted_devices`，给 `sessions` 增加可空 `device_id`。有效期设置在 `settings.browser_login_days` 保存，首次为 90，0 表示长期；不新增表、不改账号、密码、文件或路径授权。

旧版 pending/rejected/revoked 记录不会被部署自动批准；用户下次正确密码登录会按新规则取得新凭据。已有普通会话不会凭空得到长期 Cookie，需要在新版页面登录一次。

部署信息单独管理：历史见 [首次认证部署](deployment-2026-10-25-auth.md)、[早期收据领取修复](deployment-2026-10-26-login-claim.md)、[默认记住登录部署](deployment-2026-10-26-default-remember.md)；最新见 [管理员配置期限部署](deployment-2026-10-26-login-policy.md)。历史文档的浏览器审批及固定 90 天规则已由本页替代。现有 v1.5.0-1 Release 安装包未重新发布，不包含本轮功能。

升级前仍需停写并备份 SQLite（含 WAL）及上传目录。旧二进制不兼容新增后的整行 INSERT；回滚应恢复匹配版本的二进制、Web 和数据库备份，不能只降级二进制。

## 验证与人工验收

自动化入口：

- 后端：`MYFOLDER_CPP_BINARY=<测试二进制> python3 -m unittest discover -s tests -p 'test_*.py' -v`。
- 前端：`npm run build`；提供 `web/dist` 于本机 4178，运行 `python tests/check_responsive.py`，覆盖 6 种尺寸。
- 临时真实后端：`tests/serve_auth_fixture.py`；浏览器审批、轮换、撤销等流程：`tests/check_auth_ui.py`。
- 真实进程重启：`tests/check_auth_restart.py`，覆盖注册获批后手动登录、新配置仅凭密码记住、连续两次真正退出/重开 Chromium、取消勾选、主动退出。
- 有效期配置实测：`tests/check_login_policy_ui.py`，验证自定义 7 天、长期模式、确认/取消、普通管理员只读和动态登录标签；重启测试增加 `--device-days 0` 可验证长期模式，`--device-days 7` 可验证自定义天数。

浏览器写入测试只连接隔离的回环实例，使用临时数据库、账号和持久化 Chromium 配置，不导入用户真实浏览器资料、不注入 Cookie、不写生产账号。测试结束关闭服务并清理临时数据。
